## 1. 为什么改「布置作业」

旧流程是「搜题库 → 一道一道勾 → 每题默认 1 分」。两个问题：

1. **选不出卷子**。离线题库几千题，老师脑子里的条件是「这几节课的知识点，易中难各几道」，
   不是一串题号。逐页翻题库既慢又容易漏。
2. **分值永远是 1 分**。题库没有「题分」概念，组卷默认 `score: 1`，于是批改台是 `0/1 分`，
   想给 3 分会被前端拦（「分数需在 0 到 max 之间」），学情得分率也跟着失真。

所以组卷改成**条件 → 草稿 → 预览可改**：老师给条件，系统给候选，人做最后决定。

## 2. 组卷

### 2.1 流程

```
选知识点（多选，显示可用题量） + 每档题数（易/中/难） + 题型过滤 + 每题分值
        ↓ compose_draft（不落库）
预览：逐题 换一题 / 上移下移 / 改分值 / 移除 ；可再「手动加题」
        ↓ assignment_save（与手工选题同一条写入路径）
草稿 → 发布
```

### 2.2 几个刻意的选择

| 选择 | 理由 |
|---|---|
| 抽题在后端（`compose.rs`） | 要跨 `question` / `question_knowledge` / `local_assignment_question` 三张表过滤并排序，前端翻页会漏题 |
| 排序 `使用次数 asc → 创建时间 desc → id asc` | 同一条件生成两次得到同一份卷子，老师才能对比；想要不同的题点「换一题」 |
| 抽不满**如实报缺口** | `gaps[].need/got` 直接显示在预览顶部。悄悄用别的难度顶替会让作业失真，也让「题库该补哪一档」这个信号消失 |
| 只从 `PUBLISHED` 且未删除的题里抽 | 草稿题不该出现在作业里，与题库列表口径一致 |
| 缺口按「实际拿到」算，不按题库总量 | 同一个知识点可能已被前面的档抽走，按总量算会给出「够」的假象 |
| `compose_swap` 排除当前全部题 | 换一题不会换出重复题；条件里没有别的题时明确返回 `null`，界面提示「没有别的题了」 |
| 分值按题型画像，存 `app_setting compose.scoreProfile` | 题库不存题分（同一道题在不同卷子里分值本来就不同）；画像只是「这次作业的默认值」，逐题可改 |

难度档与试卷蓝图对齐：易 1–2 / 中 3 / 难 4–5，避免同一产品里两套说法。

### 2.3 命令

| 命令 | 作用 |
|---|---|
| `compose_pool(subjectId)` | 按知识点 × 难度统计可用题量，界面拿来显示「可用 N」 |
| `compose_draft(DraftInput)` | 生成草稿 `{questions, gaps}`，**不写库** |
| `compose_swap(SwapInput)` | 同档、同知识点、同题型另抽一道 |

`DraftInput`：`subjectId`、`knowledgeIds[]`、`counts{easy,middle,hard}`、`types[]`、`exclude[]`。

## 3. 讲评清单

批改备注（`local_attempt.remark`）以前**只写不读**——本地没有学生端，同步只推题库三张表。
讲评清单是它的第一个真实读者：以**题**为主体，学生名单是附属信息。

- **口径**：只取每个学生最近一次提交（`superseded_at is null` 里 `submitted_at` 最大的
  `submission_id`）；`correct = 0` 或 `score` 未满都算错，半分题单独计入 `partial`；
  空答、未批分别计数，不混进「错」。
- **排序**：`rank` 在**后端**算（错得多优先 → 同错数看得分率低），界面与打印稿共用一套，
  不出现两种「最该讲的题」。
- **界面**：抽屉里给 `先讲这三道` + 逐题记录（错的人、批改备注、知识点），可「只看有人错的」。
- **打印**：`src/lib/review.js` 拼自包含 A4 HTML（内联 CSS、无脚本、无外链），
  公式用 `latexToPlain` 降级成可读写法——打印通道离线可用，不能引 KaTeX 字体。
  另给 `导出 CSV`（一行一题，带 BOM，Excel 直接认中文）。

## 4. 边界（明确不做）

- **不做「自动判卷」**：抽题只给候选，分数永远由老师确认（沿用既有硬原则）。
- **不做「按薄弱知识点一键组卷」**：数据已经有了（学情页的薄弱点），但它需要「这个班先补哪三个」
  的产品决策，先不把两件事绑在一起。
- **不做题库「标准分」字段**：会与作业题分形成第二个真相。
- **不做学情页批注列表**（原规划的出口 B）：讲评清单已经覆盖课堂场景，个人页再加一份属于重复展示，
  等有真实使用反馈再说。
- **不做家长反馈单**（出口 C）：家长周报（`progress.rs` + `report.js`）已经承担了这件事。
