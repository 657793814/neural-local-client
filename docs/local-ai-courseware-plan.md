# 本地 AI 课件：变量提示词、现有讲义整理与多格式导出

> 状态：已实施（验证证据与未覆盖项见 §11）｜提出：2026-11-18｜范围：仅 `local-client`，不改中心系统与知识库侧 3D 课件。
>
> 本文承接 [本地优先教学能力规划](local-first-teaching-plan.md) §8。旧「AI 只补题」的边界由本次决策取代：AI 既可生成整份讲义，也可把老师已有讲义整理成统一草稿；题目生成仍沿用草稿校对，不直接正式发布。

## 1. 产品结论

本地课件形成两条入口、一个内核：

- **AI 生成课件**：填变量 → 生成可见、可改、可复制的提示词 → 调本地配置的模型 → 校对 → 入库/导出。
- **导入现有讲义**：选择多个 DOCX/PPTX/PDF/Markdown/TXT/HTML → 本地提取 → AI 统一结构 → 原稿对照校对 → 入库/导出。
- **统一内核**：两条链路都落到版本化 `HandoutSpec` 草稿，共用课件库、HTML 预览、题库挂接、班级布置和导出器。
- **原稿优先**：导入默认只整理格式，不改写教学内容、不补答案；原文件永久保留，整理结果生成新版本，不覆盖原稿。
- **离线边界**：文件解析、图片管理、课件编辑、HTML 预览与文档生成均在本机；只有用户主动调用 AI 时才访问其配置的模型端点。

## 2. 页面与主流程

课件首页保留课件卡片、搜索、学科筛选、HTML 导入、预览和班级布置，新增/调整三个主入口：

1. **AI 生成课件**：打开左右分栏工作台。左侧配置变量、内容结构、素材和输出；右侧实时显示提示词。
2. **导入现有讲义**：多选文件或整个批次，显示等待/解析中/待校对/失败/已入库状态；单份失败不阻塞整批。
3. **手动新建**：保留现有表单编辑器，作为不依赖 AI 的入口。

AI 生成工作台提供「保存草稿、复制提示词、调用模型生成、恢复默认模板」。手改提示词后标记为自定义；变量变化可以重新套用模板，但不能静默覆盖手改内容。

生成或整理完成后进入校对：可改标题、教学目标、知识清单、例题/练习、答案解析、小结作业和本地图片；确认后编译入库。失败时保留提示词和原始模型返回，不覆盖上一次成功草稿。

## 3. 统一草稿与内容结构

### 3.1 草稿

沿用 `local_courseware.lesson_spec_json` 中的 `HandoutSpec`，向后兼容旧 JSON；新增字段全部可空/有默认值。草稿包含：

- 基本元信息：课题、学科、年级、章节、知识点、简介。
- 教学变量：常规课/专题课、课时、学生情况、难度、重点难点、教学风格、补充要求。
- 内容：教学目标、情境导入、知识清单、例题、变式、拔高、思维训练、小结、作业。
- 素材：稳定图片编号、课件内相对路径、原始文件名、说明、建议位置和是否必须使用。
- 来源追溯：导入原稿相对路径、内容哈希、页码/幻灯片编号、警告和 AI 整理模式。

### 3.2 常规课程

情境导入 → 学习目标 → 新知讲解 → 例题/活动 → 巩固练习 → 易错提醒 → 课堂小结 → 作业。

### 3.3 专题课程

专题背景 → 核心概念/方法 → 类型拆解 → 典型例题 → 变式与综合应用 → 易错点 → 方法清单 → 专题训练。

两种模式共用 `HandoutSpec`；模式只改变默认提示词结构和内容映射，不制造平行数据格式。

## 4. 变量化提示词

### 4.1 内置变量

| 分组 | 变量 |
|---|---|
| 基本信息 | `{{subject}}`、`{{title}}`、`{{grade}}`、`{{duration}}`、`{{audience}}` |
| 教学内容 | `{{content_mode}}`、`{{chapter}}`、`{{knowledge_points}}`、`{{objectives}}` |
| 教学要求 | `{{difficulty}}`、`{{teaching_focus}}`、`{{teaching_difficulty}}`、`{{teaching_style}}` |
| 结构 | `{{outline}}`、`{{example_count}}`、`{{exercise_count}}`、`{{custom_instruction}}` |
| 本地素材 | `{{reference_questions}}`、`{{reference_text}}`、`{{images}}` |
| 输出 | `{{file_types}}`、`{{slide_count}}`、`{{document_length}}`、`{{theme}}`、`{{output_directory}}` |

支持自定义键值变量。变量由 Rust 确定性替换；必填项为空时明确提示，可选项显示「未指定」，不能把未替换的 `{{...}}` 静默发给模型。

### 4.2 通用模板

提示词依次包含：角色与任务、教学变量、内容结构、原始素材、图片清单、质量约束、输出协议。学科只追加一段学科要求，不维护几十套模板。

- 公式使用 `$...$`；JSON 中的反斜杠必须转义。
- 不编造事实、题目、图片内容或来源。
- 导入整理模式默认逐字保留教学内容，只判断标题/讲解/例题/练习/答案等角色。
- 本地生成模式要求只返回符合 `HandoutSpec` 的 JSON 草稿。
- 外部智能体模式沿用相同正文，附上目标文件、输出目录和图片编号；没有文件工具时返回结构化草稿。

模型 JSON 统一走现有 `llm::json` 修复与解析，再经 serde 校验，不在命令层另写截取逻辑。

## 5. 本地图片

用户通过文件选择器添加 PNG/JPEG/WebP/GIF，不依赖手输路径。每张图记录：图号、原始文件名、说明、使用位置和必须/可选。

- 添加时复制进 `assets/courseware/<draft-or-id>/`，后续使用相对路径，原文件移动不会丢图。
- 纯文本模型只收到图片说明和占位，不能假装看过图片。
- 视觉调用首版只附用户选定的一张图；多图提示词保留完整清单，不伪造多图理解能力。需要多图理解时可逐张处理。
- 复制提示词给外部智能体时，本地路径不等于外部可访问；同时提供「打开图片目录/导出素材包」，提示词用「图1、图2」稳定引用。
- HTML、DOCX、PPTX 均实际内嵌图片，不保留本机绝对路径依赖。

## 6. 现有讲义批量导入

### 6.1 分工

- **本地解析**：DOCX 读取 WordprocessingML；PPTX 按幻灯片顺序读取 DrawingML 与备注；Markdown/TXT/HTML 读取文字；PDF 复用 CoreGraphics 逐页栅格化和本机 OCR。
- **AI 整理**：只接收抽取后的文本与来源位置，识别标题、目标、讲解、例题、答案、解析、小结和作业。
- **无模型降级**：本地解析仍生成待校对草稿；AI 失败可稍后重试，不丢整批。

### 6.2 两种整理模式

- **仅统一格式（默认）**：保留原文，不改写、不补答案、不新增知识点；未知元信息留待确认。
- **整理并优化**：允许润色和补全，AI 新增内容在校对页标记，老师确认后入库。

### 6.3 任务与判重

新增本地导入任务表，每份文件独立记录：来源路径、原稿副本、SHA-256、状态、抽取文本、草稿、警告、错误、课件 id 和时间。

- 同内容默认标记重复并跳过；用户可显式重试生成新版本。
- 单文件失败不影响其他文件，支持失败项重试。
- 前端轮询任务列表，模型调用不阻塞窗口线程。
- 原稿与页码/幻灯片编号可追溯；复杂动画、SmartArt、扫描模糊和公式识别问题如实警告，不承诺 1:1 还原。

## 7. 导出

模型不直接生成二进制文件，统一从校对后的 `HandoutSpec` 导出：

| 格式 | 实现与边界 |
|---|---|
| HTML | 沿用五道闸与单文件渲染，断网预览、投屏与打印。 |
| DOCX | Rust 生成 Office Open XML 包：标题层级、段落、列表、题目、答案解析与嵌入图片。 |
| PPTX | Rust 生成 Office Open XML 包：封面、目标、知识讲解、例题/练习、总结作业；16:9，每页控制信息量，图片实际嵌入。 |
| PDF | 优先使用本机可用浏览器的无头打印生成真实 PDF；没有可用浏览器时明确降级为打开系统打印页，由用户存储为 PDF，不生成伪 PDF。 |
| JSON | 导出统一草稿供备份、外部智能体回传和再次导入。 |

所有导出通过系统保存框选择位置；同名文件不静默覆盖。导出器有 ZIP 结构/关键 XML/内容逃逸和图片嵌入测试。

## 8. 模型设置

新增「课件生成」与「课件整理」两个用途，共用模型池和 429 冷却/失败切换：

- 课件生成允许较完整的内容创作。
- 课件整理默认低创造、高保真，扫描件需要支持视觉的模型。
- 页面沿用模型选择器；Key 只在 Rust 侧读取，提示词和导出文件不包含 Key。

## 9. 数据与兼容

新增迁移只增不改：

- 扩展课件草稿所需的图片和来源追溯存储。
- 新建 `local_courseware_import` 任务表。
- 旧 HTML 课件、旧 `HandoutSpec`、题目挂接和班级布置保持可读可用。

原稿、图片和生成文档放 `assets/courseware/`，数据库只存相对路径。清理工具必须保护被课件或导入任务引用的文件。

## 10. 验收口径

1. 填常规课变量并添加一张本地图 → 提示词实时更新 → 复制文本含图号与素材说明 → 本地模型返回可校对草稿。
2. 切换专题模式 → 默认大纲变化；手改提示词不被变量调整静默覆盖。
3. 批量导入 DOCX/PPTX/PDF → 各自状态和原稿保留 → 默认模式不擅自补答案 → 失败项可独立重试。
4. 同一文件重复导入提示判重；AI 不可用仍能看到本地解析结果。
5. 同一草稿导出 HTML/DOCX/PPTX/PDF → 文件可打开、文字不是乱码、图片实际嵌入、内容一致。
6. 断网可编辑、导入本地解析、预览和导出；控制台无错误；旧课件与班级布置正常。
7. `cargo test` 与 `npm run build` 通过；主路径另做真实文件冒烟并记录证据。

## 11. 实施记录

### 11.1 实际落地（2026-11-18）

- **统一草稿与提示词**：`local-client/src-tauri/src/courseware/mod.rs` 扩展向后兼容的 `HandoutSpec`、受管图片与来源追溯；`prompt.rs` 实现变量替换、常规/专题大纲、本地与外部草稿解析；`render.rs` 内嵌图片，HTML 不再携带原图绝对路径。
- **AI 工作台**：`local-client/src/pages/CoursewareAi.jsx` 提供教学变量、自定义提示词、参考素材、图片清单、打开图片目录、本地模型生成、外部 JSON 回传与草稿恢复；`Courseware.jsx` 统一校对、暂存、入库和导出。
- **批量导入**：`source.rs` 负责 DOCX/DOCM、PPTX、PDF、Markdown、TXT、HTML 本地抽取；`ingest.rs` 负责受管原稿、逐文件状态、判重、重试、无 AI 草稿、对照校对和统一入库；前端为 `CoursewareImport.jsx`。
- **真实导出**：`office.rs` 生成 DOCX/PPTX OOXML 并嵌入图片，PDF 走本机 Chromium，无浏览器时明确降级系统打印；HTML/DOCX/PPTX/PDF/JSON 共用校对后的同一草稿，禁止静默覆盖。
- **模型与命令**：`llm/mod.rs` 新增 `courseware` / `courseware_import` 用途；`commands.rs`、`main.rs`、`permissions/local.toml` 和 `src/lib/api.js` 完成命令与 ACL 注册，模型调用在后台执行。
- **迁移与保护**：新增 `migrations/0014_courseware_import.sql`，`db.rs` 升到 `user_version=14`；`storage.rs` 的无主资源统计和清理均跳过 `assets/courseware/**`。
- **随包说明**：更新 `local-client/src/help/courseware.md` 与 `local-client/README.md`。

### 11.3 真实文件冒烟证据

冒烟测试先编译一份包含中文内容与必需 PNG 的 `HandoutSpec`，再从同一课件 id 导出五种格式并实际读取产物：

- HTML 含中文题干、图片说明与 `data:image/png;base64,`，不含最初图片的绝对路径；再次导出同名文件会被拒绝。
- JSON 可反序列化为同一 `HandoutSpec`，图片说明与相对路径保留。
- DOCX/PPTX 均作为真实 ZIP/OOXML 打开，读取关键 XML 确认中文标题、题干与图注，并确认 `word/media/image1.png` / `ppt/media/image1.png` 实际存在。
- 本机 Chrome 157 无头打印生成真实 PDF，产物大于 500 字节且文件头为 `%PDF-`，不是改扩展名的伪 PDF。
- 冒烟使用系统临时目录，完成后自动删除，不在项目目录留下验证文件。

### 11.4 剩余验收边界

- 未使用老师的真实模型端点做联网生成或视觉识图验收；模型 JSON 修复、草稿保留和失败降级已测，但具体模型的内容质量仍需在校对页人工判断。
- DOCX/PPTX 已做 OOXML 结构与内容读取验证，未逐一在不同版本的 Microsoft Office / WPS 图形界面里人工打开；复杂排版兼容性仍以实际办公软件验收为准。
- DOCX/PPTX 抽取有结构测试；真实扫描 PDF 的 OCR 清晰度、复杂公式、动画和 SmartArt 不承诺一比一还原，需用老师实际讲义抽查。
- 本轮未做隔离账号下的桌面窗口逐按钮人工验收；前端生产构建、命令 ACL 和 Rust 主链路已通过，真实模型与页面交互仍按 README 手工清单验收。
