# 离线批改的「得分 + 评语」怎么落地（规划）

> 状态：**规划，未动工**（2026-11-18）
>
> 关联：[主观题批改与班级作业](../../neural-knowledge-base/docs/product/subjective-grading-and-class-assignments.md)、
> [本地题库客户端规划](local-question-bank-client-plan.md) §18（拍照批改）、
> [手机拍照 → 本地批改联动](local-phone-photo-submission-plan.md)、
> [试卷管理 P0](local-paper-management-plan.md)（题分与总分口径）

## 1. 先说结论

本地批改台现在的「得分 + 评语」是从中心那套**有学生账号**的批改界面照搬过来的，搬到离线单机环境后两头都不落地：

- **得分**：题库没有「题分」这个概念，作业组卷时每题默认 1 分，于是批改台显示 `0/1 分`，老师想给 3 分会被前端拦下（「分数需在 0 到 1 之间」）。
- **评语**：写进去之后**没有任何界面再读它**——本地没有学生端，同步又只走题库（`sync.rs` 只推 question 三张表），所以评语是纯写入的死字段，输入框却写着「可选，学生能看到」。

这两件事都不是 bug，是**产品模型没对齐**。规划方向：

1. **题分属于「作业 / 试卷」，不属于题库。** 题库只提供题型与难度，作业组卷时按「分值画像」带出默认分（选择 3 分、填空 4 分、解答 10 分这种），老师可逐题改；批改台的满分以作业为准。
2. **评语在离线端要换个身份：从「给学生看的评语」改成「教师自己的批改备注」，并给它一个真实出口**——讲评清单、学情页批注、家长反馈单。学生可见的评语只在中心端（有账号、有作业详情页）成立。
3. **批改动作按「判定 → 给分 → 反馈」三层拆开**，判定复用题库答案与 AI 抄录建议，给分支持满分/半分/0 与步骤分，反馈进讲评而不是黑洞。

不改的底线：照片只是评分依据，分数必须老师确认（沿用既有硬原则）。

## 2. 现状盘点（以代码为准，2026-11-18）

| 环节 | 现状 | 代码位置 |
|---|---|---|
| 题库题分 | **没有**。`question` 表只有 type / difficulty / 知识点，没有任何分值字段 | `migrations/0001_init.sql` |
| 作业题分 | 每题一个 `score`，建表默认 1，组卷表单也默认 `score: 1` | `0004_teaching.sql`、`pages/Assignments.jsx`（`teach-score` 输入框、`score: 1`） |
| 批改台给分 | `max = item.maxScore`（默认 1），超出直接报错「分数需在 0 到 max 之间」 | `pages/Grading.jsx`（`saveGrades` / 逐题 `<input max={item.maxScore}>`） |
| 评语写入 | 写 `local_attempt.remark`，保存后回填到输入框 | `pages/Grading.jsx`、`pages/Assignments.jsx`、`teaching.rs::grade` |
| 评语读取 | **零处**。没有学生端、没有报表、没有打印，学情页也不显示 | 全仓 grep `remark` 只在批改界面里循环 |
| 教学数据同步 | **不出去**。`sync_outbox` 只登记 question / question_tag / question_knowledge | `sync.rs` |
| 纸质作业判分 | 代提交把全部题置 `correct = null`（待批），客观题也不自动判 | `grading.rs::paper_submit` |
| 中心端批改 | 有学生账号：学生作业详情能看到得分、评语、批改时间；教师端 `SubmissionGrader` 同一套 `score + comment` | `front-src/neural/LearningFlow.jsx`、`Papers.jsx` |
| 学情 | 掌握度只看 `correct` / `score` 与满分比例，不看 remark | `insights.rs::mastery_of` |

一句话：**得分缺「题分来源」，评语缺「读者」**。

## 3. 问题拆解

1. **P1 分值口径断裂**：题库无题分 → 作业默认每题 1 分 → 批改台满分错 → 学情「得分率」也失真（5 题各 1 分时，一题错就是 80 分）。
2. **P2 评语无出口**：教师写完就再也看不到，写它的动机只剩「万一以后有用」。
3. **P3 批改动作只有「一个数字 + 一个文本框」**：没有步骤分、没有错因、没有「满分/半分/0」的快捷动作，跟「拍照批改」这条主链路不匹配。
4. **P4 两端语义混用**：同一个字段 `remark`，中心叫「评语（学生可见）」，本地其实只是教师备忘，UI 文案没区分，用户自然觉得「这是联网才有的功能」。
5. **P5 客观题在纸质作业里也要手判**：`paper_submit` 全 pending 是对的（照片里看不出选项），但批改台没把参考答案摆出来给老师对照（本轮已补，见 §7）。

## 4. 方案

### 4.1 题分：作业带分值，题库只给建议

- **不在 `question` 上加「题分」列。** 同一道题在不同卷子里分值本来就不同，题库存一个「标准分」只会制造第二个真相。
- 新增**分值画像**（不落表，存 `app_setting`）：`{SINGLE: 3, MULTI: 4, FILL: 4, SOLVED: 10, ...}`，老师可改，记住最近一次。
- 组卷（布置作业 / 建试卷）时按画像给每题预填分，并显示「合计 N 分 · 建议 X 分」；作业的 `total_score` 仍是 `sum(score)`（现有实现不动）。
- 批改台顶部显示 `本题 10 分 · 本份 100 分`，得分输入框 `max` 取作业里的分，`min=0`，`step=0.5`；提供 `满分 / 一半 / 0` 三个快捷按钮（P1）。
- 试卷侧已有 `local_paper_section.unit_score` 与「总分固定」口径（P0 已落），作业这边对齐同一套说法即可，不新建模型。

### 4.2 评语：改成「批改备注」，并给它三个出口

先把名字和文案改对，再谈功能：

- 本地：`评语` → **`批改备注（仅本机可见）`**；占位符改成「写给自己的话：错在哪、下次讲什么」。
- 中心：保持 `评语（学生可见）`。两边共用 `remark` 字段，但 UI 文案必须区分，别让人以为离线写的评语学生能收到。

三个出口，按价值排序：

| 出口 | 做什么 | 成本 | 价值 |
|---|---|---|---|
| **A. 讲评清单**（推荐先做） | 班级维度把「题 → 错因/备注 → 涉及学生名单」汇总成一页，可打印 / 导出 CSV；上课讲评直接照着念 | 低（读 remark + 组页 + 复用打印链路） | 高：评语第一次真正被用上 |
| **B. 学情页批注** | 学生个人页的最近作业里显示每条批改备注，老师找学生谈话时按页翻 | 低（`student_insight` 多带一个字段 + 一段列表） | 中 |
| **C. 家长反馈单** | 按学生出「本次作业得分 + 2–3 条备注 + 建议」的 A4 单页，走试卷那套打印 | 中（新模板 + 打印入口） | 中 |
| D. 同步成中心评语 | 绑定中心作业后把 remark 推过去，学生端可见 | 高（教学实体 outbox 仍未做） | 未来 |

### 4.3 给分动作：从「一个数字」到「三层」

1. **判定**：客观题按题库答案自动判（在线作答已如此）；纸质的先全 pending，老师对着照片核，核完点「对 / 错」。
2. **给分**：满分预填（省一次输入）、`满分/一半/0` 快捷键、`0.5` 步进；主观题支持「步骤分」= 若干得分点勾选后自动求和（P2，先不做，留字段）。
3. **反馈**：错因标签（`计算错 / 思路错 / 抄错题 / 未作答 / 书写不清`）+ 备注。错因进讲评清单与学情「共性错因」，比一段自由文本可统计。

### 4.4 错因标签（P2）

新增 `local_attempt_tag(attempt_id, tag)`，或复用 `question_tag` 的写法但单独一张表（语义不同：一个是题目属性，一个是这次作答的问题）。学情「共性错题 Top5」下一版可加「共性错因」。

## 6. 交互草图（批改台）

```
┌ 顶栏：班级 / 作业 / 待批 6 份 · 本份 10 题 100 分 ─────────────┐
├ 左：整页照片 + 切题        ├ 右：逐题（题号 · 题型 · 满分）      │
│                            │  题干（Rich 渲染）                │
│                            │  学生答案 / 参考答案（RichInline）  │
│                            │  [满分] [一半] [0]  ← 快捷键       │
│                            │  得分 [ 8 ] / 10                  │
│                            │  错因：计算错 思路错 …（chips）     │
│                            │  备注（仅本机）[            ]      │
├ 底部：合计 82 / 100  [保存批改] [存并下一份 ⏎] ────────────────┤
```

键盘流：`1–9` 给分百分比（或直接输入）、`Enter` 保存并下一题、`J/K` 上下题。目标是一份 10 题的卷子 60 秒批完。

## 7. 本轮已顺手修掉的（不属于规划范围）

- 批改台「学生答案 / 参考答案」原来是裸 `<span>{...}`，`$\left[-2, \frac{7}{3}\right]$` 会原样显示成 LaTeX 源码；现已统一走 `RichInline`，并且**客观题也显示参考答案**（纸质卷子里的选择/填空以前没有答案可对照）。
- 作业批改抽屉、课件选题器、错题本、学情「共性错题」的题干同理改为 `RichInline`。
- 手机上传失败（「网络中断或服务已关闭」）根因是监听套接字非阻塞被 `accept()` 继承 + 请求体一次 `read_exact`；已修读请求与 413 提示，并在手机端先压缩成 JPEG 再传。详见 `local-phone-photo-submission-plan.md`。

## 8. 分期与验收

| 期 | 范围 | 验收 |
|---|---|---|
| **P1（3–4 人日）** | 分值画像 + 组卷预填 + 批改台快捷给分 + 文案改「批改备注」 | 布置 10 题作业默认合计 100 分；批改台给 8 分不再被拦；保存后学情得分率按 100 分制算对 |
| **P2（3–5 人日）** | 讲评清单（班级维度，打印/CSV）+ 学情页显示备注 | 一个班 30 人批完能出 1 页讲评清单；学生个人页能看到「老师批注」 |
| **P3（2–3 人日）** | 错因标签 + 步骤分 + 共性错因 | 错因可统计；步骤分求和等于得分 |
| **P4（不排期）** | 教学实体 outbox → 中心评语可见 | 需中心端配合，见 `local-first-teaching-plan.md` §7.1 |

## 9. 待定（动工前要定）

1. **分值画像的默认值**：按「题型」一套（选择 3 / 填空 4 / 解答 10），还是按「学段」再分（初中 100 分卷 vs 高中 150 分卷）？建议先只按题型，用最近一次记住的值覆盖。
2. **评语是否要「学生可见」的暗示**：如果将来一定不做同步，文案就彻底写「仅本机」；如果打算做 P4，可以先写「暂不发送给学生」。
3. **讲评清单的入口放哪**：批改台顶栏 / 学情页 / 作业详情三选一。建议放作业详情（一份作业一个清单），批改台只留「批完可以生成讲评单」的提示。
4. **错因标签是否允许自定义**：内置 5 个够用就先固定，别一上来做标签管理。

## 10. 明确不做

- 不给题库加「标准分」字段（会与作业题分打架）。
- 不在离线端做「学生登录看评语」——本地客户端是单用户，学生不是本地账号（既有硬原则）。
- 不做按题给「等级制」（优良中差）与百分制并存，先把百分制分数算对。
- 不为评语做富文本编辑器：一行文本 + 错因标签就够，评语的读者是老师和讲评清单。
